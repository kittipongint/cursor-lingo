# Contributing to CursorLingo

Thanks for helping! Bug reports, wrong-fix reports, test cases and code are all welcome. You can write in English or Thai.

ยินดีรับทุกการมีส่วนร่วมครับ ไม่ว่าจะเป็นการแจ้งบั๊ก แจ้งคำที่แก้ผิดหรือไม่แก้ เพิ่ม test case หรือส่งโค้ด เขียนเป็นภาษาไทยได้เลย

## The quickest way to help: report a wrong fix

Auto-fix is tuned to change correct text very rarely, so every wrong or missed fix found in real use is valuable.

- Open an issue with the **Wrong fix or missed fix** form (also in the app menu: *Report a Wrong Fix or Bug…*), or
- add the word to [`tests/cases.tsv`](tests/cases.tsv) yourself and open a pull request.

Each line in `tests/cases.tsv` is the layout that was on screen, the text exactly as it appeared, and what should happen, separated by tabs:

```
en	l;ylfu	fix
th	ะ้รห	fix
en	camelCase	keep
```

To see what the detector does with a word:

```bash
c++ -std=c++17 -Wall -I core tests/layoutfix_test.cpp -o /tmp/lf_test
```

```bash
/tmp/lf_test en "l;ylfu"
```

```
on screen (en): l;ylfu
other layout:     สวัสดี
at Space:         converts
while typing:     converts
```

Run `/tmp/lf_test` with no arguments (from the repo root) to run every test, including `tests/cases.tsv`.

**Precision comes first.** A `keep` case that fails is a bug. A `fix` case that fails may be a known limitation: words that are plausible in both languages (`muj` = ที่, `mew` = ทำไม) are left to double Shift on purpose.

## How the code is organized

| Path | What |
|------|------|
| `core/layoutfix.h` | The detector, shared by both apps: key tables, English trigram model, Thai syllable grammar, `shouldConvert`, `convertText`. Header-only, no dependencies. |
| `core/en_model.inc` | Generated by `tools/gen-en-model.py`; don't edit by hand. |
| `macos/CursorLingo.swift` | The whole macOS app (AppKit, CGEventTap). |
| `windows/CursorLingo.cpp` | The whole Windows app (Win32, low-level hooks). |
| `tests/` | `layoutfix_test.cpp` and `cases.tsv`. |

Each app is one file on purpose: easy to read, to audit and to build without a toolchain setup.

## Building

- **macOS:** `./install.sh` (builds, signs ad-hoc or with your Developer ID, installs to /Applications), or `macos/build.sh` to build only.
- **Windows:** `windows\build.bat` (Visual Studio 2022 / Build Tools + CMake), or cross-compile with MinGW-w64 as shown in the README.

## Ground rules for changes

CursorLingo sees what people type, so trust is the product:

- **No network access**, telemetry, update checks or crash reporting.
- **Never log or store typed text.** Only the current and last word live in memory. The only exception is the personal word list, which the user builds deliberately with double Shift and can clear from the menu.
- **Skip secure input** (password fields) and terminals.
- **Keep the clipboard intact.** If you must use it, restore it.
- **Off by default.** Anything that observes keystrokes stays opt-in.

And for code:

- Match the style around you; keep both apps single-file and dependency-free.
- A detector change should come with the cases that motivated it, and must not make any existing `keep` case fail.
- Behavior changes should land on both macOS and Windows, or say in the PR why not.

## Adding another layout

The detector currently knows US English and Thai Kedmanee. To add one (e.g. Thai Pattachote, or another language pair), you need: the key table in `core/layoutfix.h`, a plausibility check for that language, the layout IDs in each app (`InputSource.fixLanguage()` on macOS, `FixLangOf()` on Windows), and test cases. Please open an issue first so we can agree on the approach.

## Releases

Maintainers bump the version in `macos/Info.plist`, `windows/CursorLingo.rc` and `windows/CursorLingo.manifest`, then push a `v*` tag. CI builds, signs and notarizes the macOS app, builds the Windows Setup.exe and portable zip, and attaches them to the GitHub release. It also builds `CursorLingo-Store-x64.msix` (workflow artifact *Store-MSIX*), which a maintainer uploads in Partner Center; the Store signs it. Its identity lives in `windows/msix/AppxManifest.xml`.
